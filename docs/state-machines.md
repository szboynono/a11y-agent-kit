# Source lifecycle and state machines

This is the **audit of all lifecycle boundaries in src**: the source-linked inventory of lifecycle,
identity, admission, persistence, review and delivery boundaries in `src/`.
It is not a mathematical algorithm proof or formal exhaustive verification.
States below include both stored status strings and descriptive resource phases;
only backticked values claim literal protocol fields. Source is authoritative
when implementation changes; update links and tests with the transition.

| Distinction | Meaning |
| --- | --- |
| **sealed ≠ complete** | Sealing ends collection. Live collections explicitly retain `complete:false`; untouched criteria and unobserved scope remain. |
| **current ≠ passed** | Integrity and source freshness say whether evidence can still be used, independently of its observed outcome. |
| **checkpoint ≠ reviewed** | A durable maker draft has `needs_review`, `scoreable:false`, `sealed:false`. Saving or submitting cannot confirm it. |
| **ignored ≠ rejected** | Inventory ignore is a maker disposition; rejection requires a separate review decision and is not automatically an established false positive. |
| **action success ≠ evidence delivered** | Browser execution, JSON/PNG persistence, bounded text preview, host image viewing, checkpoint ACK and submission ACK are separate boundaries. Check every receipt and original record. |

`schema.js`, `audit/schema.js`, `wcag.js`, `pixels.js`, `summary.js`,
`audit/error-details.js`, and the catalog JSON files supply validation, metadata,
pure calculation or formatting; they own no independent persistent lifecycle.
`index.js` lazy exports, `cli.js` dispatch and `server.js` registration expose the
machines above; they do not introduce another review or freshness authority.
Tests listed here are regression evidence for selected paths, not a claim that
all possible schedules, sites, browser events or I/O failures are covered.


The v2 native submit path validates common UTF-8 fields before sealing. After seal, mapping/binding and bounded success construction must succeed before `submitted`; a retained `sealed/unsubmitted` proposal can be corrected and resubmitted using retained evidence. Collection cannot resume. Persistence faults end the cell incomplete/unknown. A common delivery key binds an explicit expected source digest; its host hook binding cannot change on replay. Native host budgets expose the shared ledger; native counters are diagnostic. Normal open-session EOF drains accepted MCP requests; opening cancellation and explicit interrupt still stop immediately.
