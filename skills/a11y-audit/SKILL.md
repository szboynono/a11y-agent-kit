description: Discover accessibility violations with local browser evidence, complete selected WCAG catalog tracking, and independently reviewed findings. Use with the developer's own coding agent; audit first, without repairing source.

## First use

Use Node.js 22.12+ and npm. Install matching Chromium with `npx -y playwright@1.64.1 install chromium`. Follow [first use](../../examples/first-use.md) to run the npm CLI from your existing agent session. See [BYOA workflow](../../examples/byoa-audit.md) for JSONL requests and report retrieval. New audits support WCAG 2.1/2.2 A/AA, default 2.2 AA.

CLI `audit-agent` only opens the session; unlike MCP `a11y_audit_start`, it runs no `snapshot` or `axe`. Send `{"tool":"step","actions":[{"action":"snapshot"},{"action":"axe"}]}` as your first request.

## Quick start (optional MCP)

After installing Chromium, register the local MCP server.

```sh
claude mcp add a11y-agent-kit -- npx -y a11y-agent-kit@0.1.1 serve   # Claude Code
```

Or in `.mcp.json` (Claude Code) `{"mcpServers":{"a11y-agent-kit":{"command":"npx","args":["-y","a11y-agent-kit@0.1.1","serve"]}}}`; or in `~/.codex/config.toml` (Codex):

```toml
[mcp_servers.a11y-agent-kit]
command = "npx"
args = ["-y", "a11y-agent-kit@0.1.1", "serve"]
```

Then, with the target reachable (a local app you started, or a site you are authorized to test; 60 tool calls, 600 s; every response reports the remaining `budget` and a `next` hint):

1. `a11y_audit_start` `{"manifest":{"projectRoot":"/abs/scratch/dir","url":"http(s)://HOST[:PORT]/"}}`, no `actions`; keep its `runId`. If the task names several viewports, put the first in `viewport` and the rest in `viewports` (for example `[{"width":390,"height":844}]`) so `coverage` can track them.
2. Over MCP, the start response already ran `snapshot` + `axe` once (counted as 1 tool call and 2 actions, what sending that step yourself would cost; `startupAxe:false` in the manifest skips it) and lists the axe violations as `startup.axe` candidates. Page 1 opens with `rules` (every violated rule: impact, SC, node count, one-line help), then one representative node per rule, then the remaining nodes. Each candidate has a `draftFinding` for a host's own findings tool (`pageUrl`, `selector` checked unique in the captured DOM with `selectorConfidence`, `axeTarget` as fallback, `stableSelector` with `stableSelectorConfidence` when one can be stated, `criterionId`, `title`, `claim` built from axe's own data, `evidenceIds`, `nodeId`). Page the rest by sending `pagination.nextRequest` (cursor only; `offset` is not supported). MCP text responses are capped at 20,000 characters (Claude Code truncates MCP output near its 25,000-token default, `MAX_MCP_OUTPUT_TOKENS`); the CLI keeps 64 KiB.
   Automatic interaction is opt-in: only `startupSweep:true` adds `startup.sweep` (exactly 1 more tool call plus one action per browser action; omitted or false skips it): up to 25 global Tab presses from the page start, recorded as ordinary `press` records, stopping on a focus cycle or when focus leaves the page (`focusOrder` rows with `evidenceId`, `nodeId`, `stableSelector` and the recorded label/text `name`; `focusLost` where focus fell to `<body>` mid-sequence; `stopped`), then a `reset` to the entry URL, then, for the narrowest declared `viewports` entry, one screenshot (`narrow.screenshotEvidenceId`) plus a snapshot. Use these as evidence: `view` the narrow PNG, and cite the press records, which count for traversal coverage only; Tab contact does not test functional keyboard operation. Focus/blur handlers may POST, navigate or persist state; reset reloads the entry URL and cannot undo site side effects. The reloaded document remains unscanned until axe runs there. Work has a 45-second soft deadline; cleanup reserves two actions and 30 seconds independently of exploration time, subject to cancellation and the hard session deadline. Remaining time bounds supported browser API timeouts; APIs without timeout support and evidence persistence may overrun the soft limit. A cleanup watchdog stops the browser if its reserve expires; failed restoration means an incomplete sweep. Then extend them: Tab to specific targets and press Enter/Space (and Escape out of what opens).
3. Early: report bound axe candidates as-is with `{"tool":"checkpoint","proposal":{"auditor":{"name":"<you>"},"adoptAxe":"all"}}`, which banks them as `source:"axe"` findings. Copy `draftFinding` only into a host's own findings/submit tool: it is **not** a proposal finding, and a checkpoint finding with `pageUrl`/`selector`/`claim` is rejected. Your own checkpoint findings use the proposal shape: `{"id":"f1","title":"...","criterionId":"4.1.2","target":{"evidenceId":"ev-0004","nodeId":"<nodeId from that record>"},"evidenceIds":["ev-0004"],"observation":"...","reason":"...","applicability":"...","exceptions":"...","scope":"..."}` (optional `method`). A rejected checkpoint returns `error.issues` (field path and message) and, for finding shape errors, `error.expectedFinding`; fix those fields rather than retrying the same proposal. Candidates with `visualEvidenceRequired` (such as 1.4.3) still need a viewed same-state PNG. Checkpoint and submit ACKs list `targets.rows`: each finding's `stableSelector`, a selector meant to survive a reload. `stableSelectorConfidence` is `unique-anchor`, `anchored-path` or `positional-fallback`. `stableSelectorLive` is a read-only match count in the current page. The selector is omitted when that count is ambiguous. Use the `stableSelector` in reproduction steps, and keep the recorded `selector` as captured.
4. re-scan with axe after each new state or page. After any action that opens a new state (edit mode, dialog, menu, expanded panel, search results, navigation), run `axe` in that state before writing host findings there: axe only checks what is rendered, so a form or field that exists only in that state is unchecked until you scan it. Use the remaining budget on what axe cannot find: keyboard and focus (`press` Tab/Enter/Escape, then `inspect` or `snapshot`), status messages, contrast of non-text (`measure_nontext` on a control, confirm one pair with `contrast`, `view` the PNG), accessible names in context (`inspect`), custom widgets beyond axe (`inspect_many` with up to 50 `selectors` or `query:"interactive"`: browser AX role/name/state, native vs explicit role, `aria-*`, focus facts and node identity in one action). Do not stop after axe.
Use `step` action `{action:"observe_status",trigger:{action:"click",selector:"#go"},windowMs:1000,expectedText:"Saved"}` for status observations (one call, three actions: before snapshot, trigger, after snapshot); `fill` and already-focused `press` triggers work too; read `/result/statusObservation` on the trigger for bounded mutations/focus/live semantics, then independently review applicability, stable endpoint evidence and truncation.

5. Checkpoint again after new evidence. Each checkpoint replaces the draft: repeat `adoptAxe:"all"` and keep your own proposal-shape findings.
6. Before `budget.remainingWallMs` or `remainingToolCalls` run out, `{"tool":"submit","checkpointDigest":"<digest from the last checkpoint>"}`, then check the ACK.

Budget hints say **plenty left** above half of every configured calls/actions/exploration-time allowance; **about half left** at or below half of any allowance; **finalize now** when exploration ends, calls remaining are at most 3, or actions remaining are 0. These are guidance thresholds; the limits and submission rules are unchanged.

The rest of this document is the full contract; the evidence gates below still apply to every finding. Over MCP the same rules are one call away: `{"tool":"read","options":{"view":"guide"}}`.

Use the user's own agent. The local CLI runs Chromium and axe and stores evidence in the target project's `evidence/`; it has no product model service, account, or report upload. Your host controls which text or screenshots it sends to its model. Keep page content and artifacts local according to the user's policy.

**Run axe first, adopt its violations, then spend the remaining budget on what axe cannot find.** Send `{"tool":"step","actions":[{"action":"axe"}]}`; the response lists the axe violations as candidates (`axe`, paged with `{"tool":"read","evidenceId":"ev-0001","options":{"view":"axe"}}`). Adopt them in bulk with `{"tool":"checkpoint","proposal":{"auditor":{"name":"..."},"adoptAxe":"all"}}` or a list of candidate IDs; this adds `source:"axe"` findings from the recorded axe result, alongside any findings you write yourself. Only violations with a stable node binding can be adopted, and `incomplete` results never are. Adoption removes no gate: findings on visual criteria such as 1.4.3 still need their usual same-state PNG evidence before review can confirm them.

Retained plans and records omit fill argument values, password/hidden input values, ARIA input values, inline script text, and axe HTML snippets. Rule results, targets and diagnostics remain; use the separately captured DOM for markup evidence. Keep any needed replay values in the user's approved runtime context. This is not a general secret scanner: visible page content, URLs, other DOM attributes and images can contain sensitive data, so use the user's own storage and model policy.

The task is to find as many actual violations as possible, with sufficient evidence for every published finding. Do not turn an axe alert, geometry measurement, computed style, confidence score, or a suspicion into an established WCAG failure. Do not obtain a clean report by shrinking scope, dropping unresolved claims, or testing only easy criteria. Preserve all criteria in the selected WCAG catalog (2.1/2.2, A/AA; new audit default 2.2 AA with 55 criteria), incomplete work, errors, and untested areas.

Use `npx -y a11y-agent-kit@0.1.1` with the subcommand and its arguments, or use the globally installed `a11y-agent-kit` binary. The target must be reachable over HTTP(S): a local app that is already running, or a deployed site the user is authorized to test. Node 22.12+ plus Playwright Chromium must be available. This workflow does not change source or system permissions. Existing `analyze/verify` commands belong to the separate historical repair workflow.

**Remote targets.** For a site that is not the user's local source, confirm the user is authorized to test it. Use a dedicated, empty workspace directory as `projectRoot` (never the open repository) and keep manifests and drafts under its `evidence/`. Resolve the canonical start URL first with a bounded redirect follow (at most 5 hops) and use the final URL. Main-document navigation stays on the manifest origin. When an error carries the source tree's additive `navigation` field (`navigation.code` is `AUDIT_NAVIGATION_BLOCKED`; the error keeps its npm 0.1.1 code), read `navigation.reason` and `navigation.suggestedAction` (`use_url`, `declare_origin` with a `manifestPatch` for `allowedOrigins`/`followRedirects`, or `stop`); apply a suggestion only for a URL or origin the user is authorized to audit, and stop that path when `overridable` is `false`. Do not crawl, sign in, bypass bot protection, or trigger side effects on production sites. See [remote sites](../../examples/remote-site.md).

## Collect and explore

Before a **delivery checkpoint** (a session instructed to checkpoint then immediately submit), collect all originals required by the claim and actual method. Reserve calls/time for checkpoint and explicit submit and check both ACKs. A successful draft or submit does not confirm evidence. Generic resumable drafts may still be saved early and updated during exploration; keep missing prerequisites and limitations explicit.

Method describes the actual basis. DOM/ARIA plus keyboard observations do not automatically mean `combined`; keyboard evidence needs a real successful global press. `visual`/`combined` requires an original stable PNG containing the target in the exact same document/state as its target DOM. Actual visual judgment requires authorized image viewing. Visual criteria require their evidence regardless of method, including omission: do not relabel claims, omit method or force `dom` to evade prerequisites. When capture/viewing is unavailable, visual prerequisites remain unresolved. ARIA observations never establish screen-reader testing.

Before a screenshot on a changing page, use `wait_for` with an observed `selector` and an explicit readiness condition (`condition:"text"` with literal `expected`, or `condition:"attribute"` with `name`/`value`; `timeoutMs` 1–5000), then take a **new `snapshot`** and `screenshot`, checking success and matching document/state. `wait` accepts only `ms` (0–5000): a delay alone guarantees no stability. On `SCREENSHOT_STATE_CHANGED`, retain the failure and allow at most one retry of that readiness → new snapshot → screenshot sequence within budget. If readiness or capture still fails, keep visual evidence unresolved. Do not alter animations or the guard, reuse old state, or infer continuous stability from matching endpoints.

For each text-contrast target (1.4.3), before the delivery checkpoint and submit/seal, retain its DOM identity/rectangle and text size, view the same-state original PNG, choose opaque text-interior/background pixel coordinates, run `contrast` with those coordinates, then read its result and view its resulting PNG. Verify the actual document/state and target binding; an axe ratio or CSS colors do not replace pixel evidence. Include the target DOM and successful `contrast` evidence IDs in that finding's `evidenceIds`. `adoptAxe` initially cites only the axe record; it does not attach later PNG/contrast records. To enrich an adopted finding, read the saved checkpoint, retain its complete proposal findings, add the needed IDs, and checkpoint that proposal without `adoptAxe` (which would append duplicate findings). Preserve other unresolved candidates. Missing prerequisites remain insufficient for confirmation, even if submit succeeds.

After sealing, existing retained evidence may support a corrected proposal, but collecting new samples requires a new run with its own evidence/document/node identities. Rebind the target using that run's actual records; never invent or backfill old evidence IDs or splice new records into the sealed collection. Report the new run separately and keep the old run's unresolved result; a new local confirmation does not repair the old report.

For asynchronous status claims, finish focus/navigation setup, then inspect the result immediately before actual activation. Retain complete original target-to-html ancestor attributes, untruncated text, identity and focus away from the result. The successful click/global press/fill remains the operation; a wait never substitutes. Preserve stable before DOM matching trigger.before, then either the exact unknown-text branch below or a successful literal-text `wait_for` on the same observed unique simple-ID node and final stable inspect matching wait.after. Derive selectors and expected text from observations; observations to learn the settled literal may precede the wait. Cite every intervening successful observation/readiness record and perform no intervening mutation. Keep same document/node and changed untruncated text. Missing prerequisites remain unresolved. See [the exact synchronous and asynchronous contract](references/evidence-policy-v2.md#status-messages-413). The later independent reviewer, not the maker, supplies `prerequisiteNotes.v2.statusMessage`, including optional `settledEvidenceId`; these are not maker proposal fields.

1. Create a local manifest with the target's absolute canonical `projectRoot` and running HTTP(S) `url`. Optional `viewport`, `maxActions`, `wallSeconds`, and `maxElements` bound the collection. Put manifests and draft findings under the target's `evidence/` so they do not change its source fingerprint.
2. For adaptive exploration, start `audit-agent manifest.json` with no manifest `actions`. Keep its local JSONL stdin/stdout session open. Send `{"tool":"step","actions":[{"action":"snapshot"}]}`, then use `read` to enumerate nodes or retrieve selected fields and `view` to obtain an original PNG file for your own image viewer. Text responses have a 64 KiB UTF-8 cap; all original data stays on disk. Save a host-authored `checkpoint` as soon as a concrete candidate has original evidence; update it after material evidence or claim changes while continuing exploration. `{"command":"finish"}` or EOF closes without automatically submitting drafts. `audit-live ... --summary` remains the older action-per-line interface, without these retrieval/checkpoint operations.
   For a fixed initial plan, run `audit manifest.json --summary`. With no `actions`, this separate batch command collects an initial DOM/ARIA view, the complete selected WCAG axe layer, screenshots, a 320 CSS px view, all four text spacing overrides, and a bounded keyboard sample. This is an initial collection, not an exhaustive audit.
3. Every record retains its original `evidenceId`, node/document/state identity, attachment SHA and original truncation flags. Start with `{"tool":"read","evidenceId":"ev-0001"}`; use `options:{"view":"nodes","fields":["tag","attributes","text","rect"]}` for node pages. Follow `pagination.next` exactly. Deferred fields provide a read handle; field chunks concatenate `data`, then `JSON.parse`. View pagination never means the original DOM was complete. Actually view PNG files returned by `view`; browser ARIA is not VoiceOver/JAWS output.
4. Choose further checks from the page and the full rubric. In `audit-agent`, append actions without replay and save a new checkpoint after meaningful evidence/claim changes. Use `{"tool":"checkpoint","proposal":{"auditor":{"name":"Your auditor"},"findings":[...]}}` with real IDs. ACK returns a durable immutable version/digest; it is `draft/needs_review`, unscoreable, and does not seal. Explicitly submit either a proposal or `{"tool":"submit","checkpointDigest":"<acknowledged digest>"}`. The batch `audit` command starts a fresh browser each invocation; keep a final finding's materials in one collection rather than mixing runs.

The local agent interface permits at most 180 actions and defaults to 60 attempted operations. Its agent manifest accepts optional `maxToolCalls`, an integer from 1 through 60 (for example, `"maxToolCalls":20`); defaults are 600 seconds total with exploration ending by 480 seconds. Shorter configured sessions reserve a proportional finalization window. Every `agent.request` call consumes an attempt, including malformed and over-limit requests, reads, inventory, views, checkpoints and submission. The preassigned request sequence is checked in serial dispatch before operation side effects; request N is allowed for cap N, and N+1 is refused. Close remains available after exhaustion. MCP invalid outer envelopes and mismatched run IDs never reach `agent.request` and retain transport-level rejection semantics; this is not a global transport budget. Leave calls and time for saving/submitting. All clocks include host idle time. After every response, read `budget.remainingWallMs`, `budget.remainingExplorationMs`, and `budget.stage`; these countdowns are advisory snapshots, so allow time for the next operation to finish. `delivery.checkpoint` is `none` or `saved`; `delivery.submission` is `unsubmitted` or `submitted`. A saved draft alone is not delivery. At `finalization`, stop exploration and explicitly submit the last acknowledged current checkpoint digest, or your current host-authored proposal, before the hard deadline. If the candidate materially changed, checkpoint the current proposal and use its acknowledged digest. Check the submit response for success and `delivery.submission: "submitted"`; a failed, interrupted, or late submission remains unsubmitted. Submission creates a proposal for independent review, not confirmed findings. A timeout with a saved draft remains incomplete and contributes no automatic official finding. `audit-checkpoint-read checkpoint.json` verifies a retained draft; after the collection is sealed, `audit-submit-checkpoint audit.json checkpoint.json` explicitly creates a needs-review proposal and preserves the checkpoint provenance. Draft recovery is not an automatic retry or completion.

`maxToolCalls` belongs only to agent configuration, accepted by `audit-agent manifest.json`, MCP `a11y_audit_start.manifest`, and `openAuditAgent`. The shared schema is exported as `auditAgentManifestSchema` from the agent module. It is removed before strict collection parsing, action validation and browser creation; batch `audit` and `audit-live` manifests still reject it. Every agent budget (start, operation/error and close receipts) exposes `maxToolCalls`, attempted `toolCalls`, and nonnegative `remainingToolCalls`. Collection/proposal reports retain their existing collection manifest and digest semantics: they do not record this agent-only cap. Preserve the supplied agent configuration and agent receipts separately when budget provenance is needed; compare underlying collection manifests after removing only this agent option. Omission retains the historical 60-call behavior and report format.

PNG bytes stay outside JSON text: `view` returns the verified original file path/hash for the host image viewer. Original node fields remain accessible via paging, not silently dropped to make the report smaller. Cursors belong to the current process; after restart begin a fresh query or field offset.

### Coverage progress

Step, read, view, inventory, checkpoint and submit responses carry `coverage`: deterministic counts from this session's own records only. It holds the fraction of wall time and calls used, Tab presses (two or more successful global presses count as a traversal), in-scope vs captured viewports, screenshots captured vs viewed, interactive elements seen vs examined individually (inspect, click, fill, measure or keyboard focus), adoptable axe candidates not adopted or cited in the latest draft, criteria cited vs the selected catalog, and distinct states/URLs. Items the records cannot support are listed in `abstained`. While less than half of the time and calls is used, `suggestedNext` names up to three untested areas. A checkpoint or submit ACK sent with less than a quarter used adds one `budgetAdvisory` line naming the checks not done. Coverage never blocks, changes findings or replaces `precheck`. Ending early with budget left is a choice, not the expected path: spend the remaining budget on the untested areas.

### Checkpoint precheck notes

Every checkpoint ACK (and the submit ACK) carries `precheck`: deterministic, advisory notes computed only from evidence already recorded in the session. Rules: `not-a-ui-component` (4.1.2/2.1.1/2.5.x on an SVG fragment or an empty, unnamed element with no recorded interactive signal), `documented-shortcut` (2.1.1 where the target or a near ancestor exposes a shortcut hint such as `(P)`, `Ctrl+`, `accesskey`), `target-size-exception` (2.5.8 on a user-agent-styled or inline link) `list-semantics-exposed` (1.3.1 on a list whose list role is exposed), `no-keyboard-evidence` (2.1.1 when no recorded Tab/Shift+Tab/Enter/Space/Escape/arrow press focused the target, a node inside it or a close ancestor) `operation-not-tested` (explicit functional 2.1.1 claims with traversal/contact but no same-document Enter/Space operation and observed result; unreachable targets need reachability evidence, not forced activation), and `name-present-now` (4.1.2/2.4.4/1.1.1 missing-name claims when the target's latest observation after the cited evidence shows a name source such as `title`, `aria-label`, text or an AX name; the note names the source and value). A rule abstains when the needed fact was not recorded, so no note is not a pass.

Notes never block, drop, rewrite or confirm a finding. Before submit, answer each note for its `findingId`: collect evidence that resolves it (for example press the documented shortcut, record a click result, inspect the operable ancestor, Tab to the target and press Enter/Space, or read its AX name with `inspect_many`), revise the claim, or withdraw it, then checkpoint again.

### MCP session start

Call `a11y_audit_start` with `{"manifest":{"projectRoot":"/abs/path","url":"http(s)://HOST[:PORT]/"}}` and **no `actions`**; send every action afterwards through `a11y_audit_request` with `request:{"tool":"step","actions":[...]}`. Use the `runId` field of the start response in every later `a11y_audit_request`/`a11y_audit_close` call. A rejected start leaves no session, so correct the manifest named in the error and call start again. Once a start succeeds, one connection holds one session: further starts return `AUDIT_SESSION_ALREADY_STARTED`, and a wrong `runId` returns `AUDIT_RUN_MISMATCH` naming the correct one.

### MCP original image output

MCP `a11y_audit_request` defaults to `imageOutput:"path"` (also when omitted).
An image-capable client can explicitly opt in with top-level `imageOutput:"inline"`
and `request:{tool:"view",evidenceId:"ev-0001"}` plus the session `runId`.
This sends potentially sensitive original page pixels to that MCP client in one
standard PNG image content block, outside text/structured JSON. The client must
read the image before visual claims. No local viewer is required for this mode
if the client can read MCP images. Other tool/inline combinations refuse.
The original evidence/state/document IDs, byte length and hash remain in the
bounded metadata. Each view still costs one request and no extra browser action.
Inline limits are 2 MiB raw PNG and 16 million pixels, inclusive; unsupported or
invalid PNGs, absent originals, changed files and oversized images return an
error without image data. These are transmission limits: agent.view's unchanged
verification can read up to 256 MiB first. Path mode remains available to clients
without image support. Delivery does not confirm inspection, currentness or
review; existing privacy and independent-review requirements still apply.
See [MCP image details](../../docs/mcp-images.md) for supported PNG encodings and
the same-UID trust boundary. Real host visual benefit remains untested.


Actions use `action` and accept only these fields:

- `snapshot`, `axe`, `reset` take no other fields.
- `inspect`: `selector`; `screenshot`: optional `fullPage`.
- `inspect_many`: exactly one of `selectors` (1-50 CSS selectors, each matching one element) or `query:"interactive"` (rendered natives, `[tabindex]`, `[onclick]`, `[role]`, ARIA-state attributes and cursor:pointer boundaries; at most 150, with omitted counts). Read-only, one action, original node/document identity like `inspect`. Rows carry Chrome AX role/name/states (input values omitted), `explicitRole`/`nativeRole`, `aria-*`, focus facts, box and a stable selector (`stableSelector`, `stableSelectorConfidence`; `inspect` step rows carry the same); page them with `{"tool":"read","evidenceId":"<id>","options":{"view":"elements"}}` and the returned `pagination.nextRequest`. `flags` are neutral observations with documented rules (`noAccessibleName`, `interactiveWithoutRole`), never findings: a finding still needs `target {evidenceId,nodeId}` from a row, applicability and exception review, and the usual evidence gate for its criterion.
- `snapshot`, `inspect` and `inspect_many` whose rendered state changes mid-capture are settled and re-captured by the product, at most 2 extra times within about 3 s, as the same one action. Step rows show `captureAttempts` when it is above 1; the record keeps `captureRetries` (reason and each changed attempt's state IDs). `DOM_STATE_CHANGED` therefore means the page kept changing through those attempts: use `wait` or `wait_for` on a settled condition before observing again rather than repeating the snapshot at once.
- `viewport`: integer `width`, `height`; `scroll`: absolute integer `x`, `y`.
- `spacing`: boolean `enabled`; its receipt records the actual CSS and representative paragraph measurements.
- `press`: `key`, using global page keyboard. It never silently focuses a selector. Each `press` step row carries `focus` (focus after the key: `on:"element"` with `tag`, `role`, `name` (the existing label/text summary, not a complete computed accessible name) up to 80 characters and `nodeId`; `on:"body"` when focus fell to the document; `on:"none"` when no element has it) and `defaultPrevented`; the step also carries `focus` after its last action, and a very large batch drops these from the rows and sets `focusNote`. `defaultPrevented:true` means the page cancelled that keydown, which is not by itself a WCAG failure and not proof that controls are unreachable, so test the key from other focus positions (including document body) before concluding; `null` means unknown (navigation, focus inside a frame, or an earlier page handler stopped the event), never read it as false. The full element is in the record at `after.active` (and `before.active` before it); read it with `{"tool":"read","evidenceId":"<press id>","options":{"view":"field","field":"/after/active"}}`. `/result/focusedElement` exists only on screenshot-style records; on others `AUDIT_FIELD_ABSENT` now lists the nearest existing paths and where focus is recorded. `click` uses `selector`; `fill` uses `selector`, `value` and marks the path mouse assisted.
- `hover`: `selector`, resolved to one main-document element; uses Playwright hover with the existing action timeout capped at 3 s. Successful results include `target`, `hovered:true`, `keyboardOnly:false`, `inputPath:"mouse-assisted"`. This observes mouse hover behaviour; it does not establish touch or keyboard support. Hidden targets fail with `AUDIT_HOVER_TARGET_NOT_VISIBLE`; other hover execution failures use `AUDIT_HOVER_FAILED`.
- `focus`: `selector`, resolved to one main-document element; uses Playwright focus and verifies the target is `document.activeElement` and matches `after.active`. Successful results include `target`, `focused:true`, `keyboardOnly:false`, `inputPath:"programmatic"`; no `keyboardPath` is added. Failure to acquire focus (including hidden, disabled, inert or nonfocusable targets) uses `AUDIT_FOCUS_NOT_ACQUIRED`. Programmatic focus does not prove natural Tab reachability; `:focus-visible` may differ from keyboard focus. Only actual global `press` supplies keyboard evidence; reset is needed to restore the keyboard-only path.
- In the default product and explicit v2 profile, each hover/focus costs one action. v2 A/B use the same strict selector-only admission and shared price; the full batch is reserved before dispatch, with no refunds for failures or unexecuted tails. Default remains 60 calls/480s; v2 explicitly uses 180 calls/600s.
- Both actions retain existing observe errors for missing/ambiguous selectors. Failed records have `success:false` and an error code; a resolved target whose action fails retains `hovered:false` or `focused:false`. Queued actions that never execute retain existing `result.status:"not_run"` and terminal errors; closed sessions reject new actions. Read `/result/hovered`, `/result/focused`, `/result/target` and `/after/active` through `read` with `view:"field"`. Success describes execution, not evidence delivery, a reviewed finding or a WCAG pass.
- `navigate`: same-origin `path`; use observed links and examine alternative presentations when relevant. Navigation creates a new document identity.
- `wait`: bounded `ms`.
- `contrast`: `foreground` and `background`, each with screenshot pixel `x`, `y`. Reproduce the view you examined, choose opaque interior samples, and inspect the actual resulting PNG and calculation. A numerical ratio does not establish the text's identity, size, or applicable exception.
- `measure_nontext`: `selector` and optional `part` (`boundary`, `indicator`, `icon`). Read-only, one action: one stable viewport PNG bound to the node and state, and candidate component-vs-adjacent colour pairs with coordinates, ratio, sample counts, uniformity and warnings (inactive, gradient/image, transparency, nonuniform, antialias-only edge, boundary maybe not needed). External foreground samples outside the target box are omitted; icon samples require a uniform touching neighbour, otherwise they warn and abstain. Ambiguous intermediate colours remain candidates. Thin anti-aliased icon strokes (1-2 px) have no uniform neighbour colour, so a fallback pair (`basis:"antialiased-core"`) is returned only when its colour equals a solid colour that a painted shape of the icon paints (`computedColorMatch:true`, `computedColor`) and nothing fades the icon (opacity, fill/stroke-opacity or a CSS filter on the shape or any ancestor). Such a pair may be cited after its `contrastRequest` and a look at the PNG. When there is no pair and a warning (`icon_colour_unverified`, with `transparency` for a faded icon or `painted_colour_unknown` for `<use>`, CSS-mask or background icons), check the icon manually: report it as needs-review or untested and do not invent a ratio. A `subpixel_stroke` warning (a painted stroke under 1 CSS px) means pixel ratios understate the authored colour: do not cite them alone. Label text and SVG `<text>` are excluded from the icon area (an icon drawn only as SVG text gets no fallback pair and needs a manual check). Observations only, no verdict. To cite a pair for 1.4.11, send its `contrastRequest` as a `contrast` action: that record, not the measurement, is the `nonTextContrast.contrastEvidenceId`. View the PNG; whether the graphic is required and any exception stay reviewer judgements.

The full `axe` record also contains `axeNodeBindings` and the bound original `nodes`. A stable `bound` row links a rule's main-document target to its original `nodeId` in that same axe `evidenceId`; it can be used directly as a proposal target. Read that original record once instead of inspecting every alert separately. Unbound, changed-state, iframe/shadow and truncated targets remain explicit and require further evidence. A binding establishes identity, not that an automated warning is a WCAG violation.

Inspect menus, dialogs, form errors, theme changes, focus order, resizing, spacing, content alternatives and the relevant complete user process. A focused element alone does not prove a visible indicator. An overflowing rectangle alone does not establish loss of readable content. Check reveal controls, scrolling, equivalent linked content and necessary two-dimensional layouts. Do not classify a logo as ordinary image text. No real screen reader tool is implemented here; leave reader-specific evidence untested.

For a custom-control claim, establish the user-perceived component and its function from the complete component, its appearance and actual activation. An event listener by itself does not establish a separate control. An equivalent native link can expose a card's shared navigation; it does not exempt a genuinely separate control from name, role or keyboard requirements. For a low-contrast presentation, retain the measured shortfall and check any actual alternate presentation and the means of reaching it. A theme switch alone does not establish a conforming alternate version, and absence of a complete conformance audit alone does not establish its failure. Record the precise supported observation and unresolved prerequisite separately.

For an explicitly frozen local resource environment, the manifest can include `networkReplay: {"manifestPath": "/absolute/project/__audit_replay/manifest.json", "sha256": "<lowercase SHA-256>"}`. The strict response manifest has `schemaVersion: 1` and `entries` with exact public `url`, relative body `file`, `sha256`, `bytes`, `status` and `contentType`. Keep it and its bodies inside the source fingerprint scope. Only verified off-origin GET/HEAD responses are replayed locally; unfrozen external HTTP/WebSocket requests are blocked. Redirects and streaming responses are unavailable in this bounded mode. Startup, action and cleanup observations remain in the report. This opt-in environment does not reproduce production headers or every external feature and is not an OS network firewall. Resource errors caused by it require an environment limitation, not a website violation. Ordinary manifests retain their existing network behavior.

### Key names for `press`

`press` takes Playwright key names, which are case-sensitive: `Tab`, `Shift+Tab`, `Enter`, `Escape`, `ArrowDown`, `Home`, `a`, `A`. `Space` is accepted (the page receives `key:" "`); a bare `" "` is rejected as an empty key. Join modifiers with `+` (`Control+/`, `Shift+Tab`, `Control+Shift+P`; `ControlOrMeta` is accepted); `Ctrl`, `Cmd`, `Command`, `Esc`, `tab` and other unknown names fail the press with an error row (`RUNTIME_ERROR`, "Unknown key"). A printed symbol is pressed as itself: `?` reaches the page as `key:"?"` with `shiftKey:false`, while `Shift+/` reaches it as `key:"/"` with `shiftKey:true`, so a handler that tests `key === "?"` sees only the former. `Control+/` and `Meta+/` reach the page as `key:"/"` with `ctrlKey` / `metaKey` set. Each modifier is also its own keydown first; `defaultPrevented` reports the last keydown, the key itself. A shortcut that does nothing may have been sent with the wrong spelling; try the other spelling before concluding it is unsupported.

## Submit evidence, then obtain independent review

Run `audit-submit audit-report.json findings.json --summary`. The input is:

```json
{
  "auditor": { "name": "The current auditor" },
  "findings": []
}
```

For every actual claim, add a unique `id`, `title`, a single `criterionId` from the fixed catalog, `target: {"evidenceId": "<real DOM observation>", "nodeId": "<real observed node>"}`, `evidenceIds` including that observation, and nonempty `observation`, `reason`, `applicability`, `exceptions`, `scope`. Optional `method` is `dom`, `visual`, `keyboard`, or `combined`. Use original IDs, not invented selectors or references. Distinct criteria on the same element are distinct claims. Do not add findings merely to fill this schema.

Submission remains a proposal. A different reviewer should inspect the original materials without the author's expected labels. That reviewer supplies `reviewer: {"name": "A different reviewer", "independentOfAuditor": true}` and at most one decision per original `findingId`: `verdict` (`supported`, `insufficient`, `rejected`), `checks` (`evidenceSupport`, `criterionMapping`, `scope`, `prerequisites`, each `supported`, `insufficient`, or `contradicted`), and a substantive `reason`. Unknown/duplicate IDs are rejected. Omitted findings stay unassessed in the original denominator; `reviewProgress` reports submitted/unassessed counts. An empty decisions array is allowed but assesses nothing. `missingEvidence` records what must be collected next. Independence is a declaration, not an OS identity guarantee.

Ordinary nonvisual decisions also supply `directEvidence: {"evidenceId":"<successful referenced same-state DOM record>","nodeIds":["<target and context nodes>"],"criterionClause":"<exact criterion token and applicable clause>","explanation":"<what the retained evidence establishes>"}`. New reviews use `directEvidencePolicy:"dom-predicates-v1"`. The citation itself is insufficient: currently only the4.1.2 missing-name ordinary predicate is implemented, for native text/number inputs, focusable sliders, and native buttons with a target-scoped empty-name ARIA `inspect` snapshot. Complete retained naming attributes/label receipts and rendered component evidence are required. Named, truncated, unsupported or unresolved components stay queued. Other ordinary criteria, including1.3.1, remain queued even with complete citations/ancestry; a parent outside a truncated snapshot does not establish relationship semantics. Do not manufacture a predicate or relabel a different4.1.2 claim as missing-name evidence.

Use `prerequisiteNotes.alternativePresentation` and `.exceptions` for a reflow finding; `.contrast` for a contrast finding must address the actual text, size/type, sampling, and exceptions. These notes are review reasoning, not a replacement for original evidence. The tool also checks the required original screenshots, state, keyboard or spacing records; this does not establish semantic predicates for all visual criteria. Use `audit-review proposal.json adjudication.json --summary`. A saved partial review exits2 and names its file; a saved review without queued findings exits0; errors exit1. Parse JSON on every exit. `--out NEW_REVIEW.json` creates an exclusive new file whose parent already exists: use the collection's own canonical run directory or a destination outside the audited project and other audit runs. Source/foreign-run outputs are rejected before writing, and existing outputs are never replaced. Without `--out`, the review is saved in the original run. Saved means written/closed, not a crash-safe guarantee.

Fresh collections have tool-stamped `evidencePolicy:"audit-evidence-2"`; this is not a manifest option. Reviewer notes for 1.4.11, 4.1.3 and 1.4.3 additionally use the structured `prerequisiteNotes.v2` contract in [evidence-policy-v2](references/evidence-policy-v2.md). Inspect a status result before and after its actual triggering operation to retain the complete original ancestor semantics. Legacy reports without the policy receipt keep their original checks and cannot be treated as new-policy evidence. A passing mechanical prerequisite gate still labels semantics `reviewer-dependent`.

For an asynchronous status summary, optionally add `settledEvidenceId` to `prerequisiteNotes.v2.statusMessage`. Keep `operationEvidenceId` on the actual successful click, global keyboard press or fill. Cite a successful `wait_for` **between** that trigger and `afterEvidenceId`, using `condition:"text"`, the original target's exact simple ID selector (for example `#status`), and literal `expected` text equal to the complete final target text. Its unique, untruncated, non-omitted result must match, and its after-state must equal the final stable DOM state. The before-DOM must still match the trigger's before-state and retain the same original node/document. Cite every intervening browser record; all must succeed in that document and be read-only DOM/image observations or matching text readiness on that target. Additional interactions, navigation, viewport/scroll/spacing changes, failed records and uncited observations prevent support. Complex/escaped/positional selectors are unsupported in this optional branch. Omit `settledEvidenceId` to keep the existing synchronous contract. Applicability, focus and ancestor-semantics review remain required.


Only findings with supported review checks and complete evidence contracts appear in `confirmedFindings`. Continue collecting missing material for `verificationQueue`; do not publish it as confirmed or silently delete it. Rejected observations remain in the original denominator. An empty or partly reviewed list never establishes that the page is accessible.

Finally run `audit-check reviewed-report.json --summary`. `current` means intact evidence and matching source, not a semantic or conformance pass. Historical declaration-only and `dom-citations-v1` reviews return `needs_review`, `reviewPolicy` and `requiresReReview:true`; their original bytes stay intact. Summaries label them, and HTML/inventory display previous confirmations as needing re-review. A code change, attachment alteration, error, incomplete collection or missing test remains visible. Read nonzero command output as JSON rather than treating it as no result. CLI success only means a command completed; full-page WCAG conformance remains `not_assessed`.

Deliver the confirmed problems with their original local evidence, clear scope and reproducible steps, plus what remains unresolved or untested. Do not claim the page is free of violations or that this tool replaces expert or real screen reader testing.

For unknown text, the reviewer-only `settledEvidenceId` alternatively admits exactly consecutive original `inspect -> click -> wait_for(condition:"attribute",name:"aria-busy",value:"false") -> inspect` on the same observed unique simple-ID status node. No intervening observation/wait/mutation; no press/fill or arbitrary predicates. Cite all four successful ordered records. All existing stable endpoint, before.after=operation.before, wait.after=final.after, original document/node, changed untruncated text, focus and complete attribute/ancestor/live-semantics checks still apply. Keep independent status-summary applicability review; substantive/uncertain cases remain queued. This reviews the observed summary, not business completion, continuity or causal exclusivity. Stale/early false with changed text may structurally pass; unchanged text refuses. There is no poll history/sample target ID; sample-and-restore remains a limitation as with literal text. Do not infer a true transition. No screen-reader or autonomous completion claim follows. See the [full evidence contract](references/evidence-policy-v2.md#unknown-text-status-summary).

## Bounded state readiness

Use explicit `wait_for` when a known target must reach a particular DOM state before collecting evidence. It uses the same main-document CSS selector boundary as `inspect`; it does not accept XPath, JavaScript, functions, or executable regular expressions. Example JSONL for an open `audit-agent` session:

```json
{"tool":"step","actions":[{"action":"click","selector":"#load-results"},{"action":"wait_for","selector":"#results","condition":"attribute","name":"aria-busy","value":"false","timeoutMs":3000},{"action":"wait_for","selector":"#results","condition":"text","expected":"3 results"},{"action":"snapshot"},{"action":"screenshot"}]}
```

This exact sequence assumes the application has those controls and literal result text. Send the same `step` request inside `a11y_audit_request` with its `runId` for MCP. The audit session accepts six request types (`step`, `read`, `inventory`, `view`, `checkpoint` and `submit`). Batch `audit` manifest `actions` and action-per-line `audit-live` accept the same action objects.

The strict variants are `condition: "attached" | "detached" | "visible" | "hidden"` with no comparison fields; `condition:"text", expected:string`; or `condition:"attribute", name:string, value:string|null`. Extra keys are invalid. `timeoutMs` is an integer 1–5000, default 3000; effective polling time is capped by the executor's remaining budget, including time spent observing the initial state. Each valid request consumes one action even on timeout. There are no automatic extra actions, alternate attempts, or retries; the single predicate is polled at intervals up to 25 ms until matched or stopped. Wall deadlines and interrupts still close the context.

All variants reject more than one matching element. `attached`, `visible`, `text`, and `attribute` require exactly one existing element. `detached` matches zero elements; `hidden` matches zero or one element failing the visibility predicate. Visibility here means non-hidden/non-collapsed computed visibility and a bounding box with positive width and height, consistent with a narrow CSS/geometry readiness check. It does not establish viewport intersection, absence of occlusion, opacity, accessibility-tree exposure, network idle, or whole-page completion.

Text compares exact DOM `textContent`, including whitespace, with no trimming, normalization, ARIA naming or screen-reader claim. Attribute comparisons use exact `getAttribute`; `null` means absence on a unique existing element, not an absent element. Literals are capped at 4096 characters and attribute names at 128 with a conventional ASCII attribute-name syntax. Readiness does not read input `.value`; password/hidden input value attribute observations remain omitted. Actual text is omitted for script elements and containers with script descendants, preserving the existing inline-script omission while comparison still uses literal `textContent`. Predicate arguments are retained, so do not supply secrets as expected literals. Other existing privacy rules remain unchanged.

Use `{"tool":"read","evidenceId":"<returned ID>","options":{"view":"field","field":"/result"}}` to retrieve the original readiness result through the existing bounded field reader; follow its chunk continuation if present. The original action record retains condition, selector, requested/effective timeout, `matched`, bounded actual observations where available, and normal before/after states and evidence ID. `AUDIT_READINESS_TIMEOUT`, `AUDIT_READINESS_AMBIGUOUS`, invalid CSS and browser errors are failed actions with retained records; invalid schema follows existing no-action-charge rules (agent attempted operations still count). `matched:true` means only that predicate was observed. Collect subsequent inspect/snapshot/PNG evidence normally; readiness does not establish evidence equivalence, node identity across captures, evidence Rule 6, a whole-criterion verdict, or an advantage over axe. Historical reports retain their original standards/labels; replay old protocols with their pinned source checkouts.

## Bounded blob content identity

`blob_digest` reads one existing main-document CSS target's literal `href` or `src`. It accepts only `selector`, `attribute: "href" | "src"`, optional positive integer `maxBytes` (default 1048576, maximum 8388608), and integer `timeoutMs` (default 3000, range 1–5000). It requires a `blob:` URL with an inner HTTP(S) origin exactly matching the current page. Missing, ambiguous, foreign-origin, null-origin and non-blob sources fail before fetching. There is no supplied-URL fetch or main-world fallback.

Example for an application that has already created `#download`:

```json
{"tool":"step","actions":[{"action":"wait_for","selector":"#download","condition":"attached"},{"action":"blob_digest","selector":"#download","attribute":"href","maxBytes":1048576,"timeoutMs":3000},{"action":"inspect","selector":"#download"},{"action":"screenshot"}]}
```

The same strict action is accepted by batch/live CLI and MCP `step`; the same six audit requests are available. Each valid attempt costs one action, with no retries. The effective deadline includes initial DOM observation and remaining executor time. Chromium reads bounded complete bytes in a separate CDP isolated world, then Node computes SHA-256 on decoded bytes. Oversize, timeout, revoked-source, navigation and browser failures retain a failed action without a partial digest. Empty blobs are valid. Exact browser-reported MIME is retained; an empty type stays empty. SHA-256 describes bytes; compare MIME separately when representation identity matters.

Successful metadata includes `algorithm`, `sha256`, byte `size`, `mimeType`, the unchanged `originalBlobURL`, selector/attribute, `complete:true` and original node/document/state binding. The isolated target reference and mutation observer are established before the initial DOM observation. Source-attribute changes and target removal/replacement are tracked through final verification, including a source changed then restored; current unique-selector and document identity must also match. The pinned target must be present in the original bounded visible DOM observation. Before/after state IDs and whole-state stability remain recorded; unrelated page changes do not by themselves invalidate target binding.

Cleanup dispatches abort/disconnect, object release and session detach independently. It waits at most 100 ms and never beyond the remaining executor budget. Late completions are handled without delaying the action result; cleanup of an unresponsive renderer is best effort until that renderer resumes or the browser context closes. A timeout still retains no digest.

Body bytes are transient in Chromium/CDP/Node memory and never written into returned evidence, CLI/MCP projections or artifacts. Metadata JSON uses existing private evidence storage. Existing DOM/PNG privacy policy still applies; URLs and visible content may be sensitive. Do not commit third-party bodies or private metadata to Git. This isolates byte reading from page-patched fetch/crypto/DOM prototypes; it does not upgrade existing DOM capture trust, establish OS authenticity, or attest a hostile page as safe.

Use the hash to identify the resource bytes. Keep the original blob UUID and URL in the evidence. Establish DOM identity, evidence equivalence and WCAG findings with the corresponding audit evidence.

## Account for retained axe observations

Send the request `{"tool":"inventory","options":{"limit":100}}` in an open generic `audit-agent` session (or as `request` in `a11y_audit_request`). Repeat `inventory` with `inventory.pagination.next` as `options`. Each request consumes the existing attempted tool/time budget and performs no browser action. Step and submission receipts advertise pending counts.

For sealed evidence, run `audit-inventory REPORT_PATH [DISPOSITIONS_PATH] [--limit 100] [--cursor TOKEN]`. Collection, proposal and review reports remain read-only. Every retained successful axe violations/incomplete **node** is an observation, including unbound targets and targets beyond the binding cap. Repeated states stay separate. Numeric rule-owned WCAG tags supply catalog-filtered mapping hints only. Inventory counts are observations/unresolved/linked/ignored, separate from candidates, findings, confirmed findings, false positives and coverage. Original candidates were already retained in collection/proposal/review reports.

Dispositions are optional; omission means unresolved. To author them, create a new JSON file directly in the original run directory with `kind:"audit-inventory-dispositions"`, `version:1`, a positive integer `revision`, `runId`, exact `collection:{reportPath,reportDigest}`, exact `proposal:{reportPath,reportDigest}` (or `null` without a proposal), `maker:{name}`, and `dispositions:[]`. Each entry has an existing `observationId` and `status:"linked"` with unique `findingIds`, `status:"ignored"` with a nonempty `reason`, or `status:"unresolved"`. Links require the original proposal maker name and findings targeting and referencing that same original evidence ID. Ignore records a maker decision; it does not establish reviewer rejection. Keep each prior revision in its own file. No automatic linking or live disposition authoring occurs before formal proposal submission.

Use `--write` only when a durable companion page is needed: each invocation writes a new exclusive `inventory-v1-<UUID>.json` in the run directory. Follow every continuation to deliver all pages; each companion is one page, with a digest of the disposition input. No old report, candidate or draft is rewritten. Supply the same report/disposition input on subsequent CLI pages. Source changes invalidate continuations. `rawPointer` addresses the original record JSON; original JSON/PNG references retain their hashes. Read huge target fields via `originalFieldRead` and apply `rawPointer`; `truncated:true` is explicit metadata, never a missing observation. Default lists contain no axe HTML or check payloads. Node read handles appear only for valid stable original bindings.

Deliver these pending counts and any companion paths alongside findings. Links require the same stable original node binding; an unbound observation remains unresolved or may be explicitly ignored with a reason. A linked incomplete observation stays incomplete; linked rejected/insufficient claims retain their review outcome separately. Failed scans, omitted or unstable bindings and unscanned scope are limitations. Use the inventory to account for retained observations. Claim confirmation and conformance require their own evidence.

## Whole retained node reads

Every node-page row, including a deferred row, provides `read`. Pass that object unchanged as `options` in a `read` request with the same `evidenceId` and outer MCP `runId`. It selects `view:"field", nodeId, field:"$node"`. Follow `pagination.next`, concatenate `data` in order, and `JSON.parse` once to recover the original occurrences with their source/state/document identities and truncation flags.

`fields` in `view:"nodes"` selects ordinary names only; `$node` is invalid there. Node-page hints and MCP schema descriptions generate that list from the same authority. Whole-node reads preserve retained scope; they do not recover observations omitted during capture.
